# 模型差异归因：改动到底起没起作用

用户给了两版模型（或同一版的不同配置）时，报告要回答的不是"谁分高"，
而是**"这一版改的那个东西，有没有用；代价是什么；要不要留"**。

本文件是那套判断的框架。它**不产生新指标**——只用已经算好的 TS / POD / FAR /
漏报率 / BIAS / RMSE / ACC / FA / 谱，做"预期特征 vs 实际形态"的对照。
指标定义见 `evaluation-metrics.md`，门槛见 `diagnostic-rules.md`（TS 系列）
与 `rmse-batch-evaluation.md`（RMSE 家族）。

> **一句话方法**：**先说清改了什么 → 推出"如果它有用，哪个数字该动、往哪动" →
> 再去结果里找那个数字。** 找不到就是没用（或没生效），找反了就是有害。
> 没有预期的对照是"数据考古"，能看出差异但说不出因果。

---

## 0. 先拿到一份能对照的改动说明

归因的起点是改动说明，不是结果表。**没有改动说明就只能报差异、不能归因**——
报告里要如实分开写："两版差异如下（事实）" 与 "差异可能来自 X（推测，待确认）"。

改动说明写成 `--change "..."` 进报告头。写得好的三条标准：

| 要素 | 反例 | 正例 |
|---|---|---|
| **改了什么模块** | "优化了模型" | "把降水损失换成 Focal Loss（γ=2）" |
| **动了哪些变量/量级** | "提升降水" | "只动了 tp 通道，其余通道权重不变" |
| **跟谁比** | "比之前好" | "与上一版同数据同起报期" |

**用户只说了"改了 X"、没说别的模块动没动**时，先问清楚——否则无法排除
"差异是别的模块带来的"。

---

## 1. 三步归因

### 第 1 步：把改动翻译成**预期特征**

每类改动都有它该留下的指纹。先把指纹写下来，再去对：

| 改动类型 | 如果生效，预期出现的特征 | 主要看 |
|---|---|---|
| 损失函数（Focal Loss / 加权） | 目标量级的 POD ↑、漏报率 ↓；**频次形态会变**，BIAS 可能一起动 | 逐等级 TS / POD / 漏报率 |
| 空间谱损失（Spectral Loss） | 高波数段 pred/obs 比值 → 1；FA ratio → 1；**小雨的空报可能↑** | 谱曲线、FA ratio |
| 极端事件重加权 | ≥50/≥100 档 TS ↑；**小雨档可能持平或略降**（权重被抢） | 高等级 TS / 命中数 |
| 后处理（QM / FM） | BIAS → 1、FAR ↓；**ACC 与谱形态基本不动**（不改场结构） | BIAS / FAR，以及 ACC 有没有被误伤 |
| 加分辨率 / 加通道 | 小尺度能量 ↑（谱高波数 ↑）、FA ratio ↑；短时效 RMSE ↓ | 谱、FA、RMSE 时效曲线 |
| 单位/口径修正 | 某个变量**整体量级**跳变（不是形态变化）；**全时效平移** | 该变量 RMSE 的时效平坦度 |

> **"整体量级跳变"和"技巧变化"长得完全不同**：技巧变化是随时效累积的、
> 是形态；单位错是**全时效同倍数的平移**、是量级。第 3 节的症状表里
> 「单位不匹配」那一条是真踩过的坑。

### 第 2 步：在结果里找那个特征

对每个模型、每个量级、每个时效，算**差值**（B − A），再看：

1. **方向对不对**——预期该涨的涨了没有；
2. **是不是只在目标上动**——见第 2 节的"波及面"检查；
3. **跨时效一致不一致**——只有短时效好 ≠ 模块好，可能是过拟合首日。

**差值永远比绝对值好读**。两个模型水平接近时（0.529 / 0.519 / 0.507 / 0.504
这种），绝对值曲线会重合成一团，差值才回答"谁在哪一档领先"。
**但 TS 报告里不再画差值图**：图统一画绝对值 + 自适应纵轴（`zoom_y=True`），
领先者与领先幅度从同一条曲线就能读出来；**差值只留在表里**（表中的
「相对主模型」列），**方向是「对比模型 − 主模型」，正值表示对比模型领先**
——写反整节结论就颠倒了。

### 第 3 步：下结论时给"代价"和"边界"

一条合格的归因结论长这样：

> 改动 B 在 ≥10mm 档把 TS 从 0.237 抬到 0.259（+0.022），
> **但 ≥100mm 档反而从 0.007 掉到 0.004**，且 ≥0.1mm 的空报率上升
> （FAR 0.496 → 0.53）。**该模块对中雨有正贡献、对强降水是负贡献**，
> 建议只在中雨量级启用，或回退后重调权重。

而不是"B 更好"。**只看涨的那一档就是在给自己找证据。**

## 2. 波及面检查（这一步最容易漏）

改一个模块，**不该动的指标有没有一起动**？这决定了这个差异是"模块效应"
还是"全局效应"。

| 检查 | 说明 |
|---|---|
| **未改动变量** | 只动了 tp，那 z500 / t2m 的 RMSE 应该**基本不动**（同一次评测里）。如果全变量一起平移了 → 差异来自评测口径或输入数据，不是那个模块 |
| **未改动量级** | 只声称改善强降水，那小雨档应该基本不动。小雨也一起涨了 → 是全局的频次/平滑度变了 |
| **未改动时效** | 模块通常在短时效生效更明显；如果连 360h 都同比例变好，怀疑是口径差异而非技巧差异 |
| **对照组** | 有没有"同数据、同起报期、只差这一个模块"的第三版？没有的话，**差异里必然混着数据/时段的影响**——报告里要写清这是混淆项 |

**跨模型比较的前提**：起报时段、站点集、窗口长度、阈值表、时效范围
**五样一致**才可直接比。少一样（比如 AIFS 多一个 ≥250 档、FGVP 的
`grade` 列写法不同）就得先对齐再比，或者在报告里明确标注"不可直接比较"。

## 3. 症状词典（从数字反推成因）

结果表里看到这些形态时，优先怀疑什么：

| 症状（数字长什么样） | 优先怀疑 | 该看哪几个数 |
|---|---|---|
| 小雨 `BIAS > 1.3` 且 `FAR` 高；强降水 `POD` 低、漏报率 > 0.95；谱高波数 pred/obs < 1 | **空间过度平滑**（把小尺度强中心抹成大范围弱降水） | 逐等级 BIAS + FAR + 漏报率、谱高波数段、FA ratio |
| `FA ratio > 1` 且**随时效恶化**；长时效 RMSE 相对暴涨；谱高波数 pred/obs > 1 | **能量发散**（预报场方差过大） | FA ratio 时效曲线、长时效 RMSE、谱 |
| `FA ratio < 1`（全时效）、谱全段偏弱 | **能量塌缩**（过度平滑到方差不足） | FA ratio、谱、ACC 衰减速度 |
| 某变量 RMSE **全时效平坦**、量级≈该场自身的量级、不随时效增长 | **单位/量纲不匹配**（不是技巧问题，是数据问题） | 该变量单独看；和其他变量比"随时效增长的形态" |
| 全变量 `BIAS` 同向偏移、RMSE 与自身量级同阶 | 时间错位 / 插值口径错（时区偏移、插值方式） | meta.json 的 `tz_shift_h` / `interp` |
| 低波数正常、高波数一起掉 | 分辨率上限 / 谱截断 / 模式有效分辨率不足 | 谱曲线拐点在第几个波数 |
| `BIAS` 远离 1 但 TS 形态正常、ACC 不差 | **频率偏差型**（场型对、频次错）——**后处理能救** | BIAS + TS + ACC 三者对照 |
| ACC 首时效 > 99% | 饱和，模型间差异已淹没在噪声里，**比 ACC 名次没意义** | 改看 RMSE 与谱（`SATURATED_ACC`） |

> 这套症状是从**降水 TS 与 RMSE 批次两个家族**实测出来的，不是文献抄的。
> 尤其"单位不匹配"那条：FengQing 的 q700 RMSE 全时效平坦在 ≈4.36
> （24h 4.359 → 360h 4.368，Δ=−0.02），而正常模型该是 0.6 → 1.9 的增长——
> **它长得跟"技巧超好"一模一样**，不熟悉就会当成优点写进报告。

## 4. 判定规则：这个模块算不算"有用"

四条全过才算。**过不了第 2 或第 3 条就写成"存疑"或"有害"**：

| # | 规则 | 门槛 |
|---|---|---|
| 1 | **方向对** | 预期该动的指标真的动了，方向与预期一致 |
| 2 | **不是噪声** | 并列门槛 **差 < 0.005 一律视为并列**，不报领先者（与 `_baseline_table` 的 ↑/↓/≈ 同一个门槛）。高量级还要先过样本量门槛（`events < 50` 仅参照） |
| 3 | **有代价评估** | 至少检查过：目标量级以外的等级、未改动的变量、长时效——**有没有变差** |
| 4 | **跨时效一致** | 改善不是只出现在一两个时效上（尤其是只在 24h） |

**名次用竞赛排名**（名次 = 比自己高的对象个数 + 1），并列同名次——
否则表里写 `3/3`、正文算出第 2，读者只会信一个。

## 5. 从归因写到"改进建议"

报告最后一节的建议，**每条都要挂在一条已确认的归因上**，
不是通用清单。触发条件与建议的对应见 `diagnostic-rules.md` §7。

写法：**现象（带数）→ 归因 → 动作 → 预期效果**。

```
1. 小雨档 BIAS 1.660、FAR 0.496 → 空间过度平滑。
   → 焦点损失（Focal Loss）降低无雨背景权重 + 频率匹配订正；
     预期 FAR ↓、BIAS → 1，代价是 ≥0.1 档 POD 可能小幅回落。
2. ≥25mm 档 TS 0.104、谱高波数 pred/obs 0.71 → 高频细节丢失。
   → 空间谱损失（Spectral Loss）+ 极端事件样本重加权；
     预期谱高波数比值 → 1、≥25/≥50 档 TS ↑。
```

**没确认归因的就不写建议**——"建议加注意力机制"这种没有数字支撑的话，
比不写更糟。

## 6. 不要做的事

1. 不要在没有改动说明时写"这个改动起作用了"——只能说"两版有这些差异"；
2. 不要只看涨的那一档就下结论，**代价与边界必须一起给**；
3. 不要用**单一时效**（尤其只有 24h）的改善论证模块有效；
4. 不要把**量级跳变**（单位/口径）当成技巧提升或下降——先排除数据问题；
5. 不要跨口径比（不同起报时段 / 站点集 / 窗口长度 / 阈值表 / 时效范围）；
6. 不要用"结果里没有"反推"数据源里没有"（缺席多半是没配气候态或 writer）；
7. 不要把差 < 0.005 的差距说成领先，也不要给并列的两家排名次；
8. 不要写没有归因支撑的通用改进建议（"建议加大模型"这类）。
