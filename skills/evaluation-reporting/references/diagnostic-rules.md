# 诊断规则（与 TS 报告对齐）

本文件描述**降水分类检验（TS 系列）结果怎么判读**。§1–§5 与
`scripts/reporting/reports/ts_report.py` 中的 `diagnose()` /
`business_conclusion()` / `recommendations()` 一一对应，智能体写报告时以代码为准，
本文件用于解释口径和边界。§6 的概率评分由 `ts_report.analysis_probability` 渲染。

---

## 0. 三条原则

1. **先看样本，再看技巧。** 样本不足或没有事件时，任何"技巧高低"的说法都不成立。
2. **比率用合计口径。** 先沿时效合计列联表（hits/misses/false_alarms）再算比率；
   计数与比率必须同口径。**禁止**把"多时效合计的 hits"和"单时效的 n_pairs"放在同一行。
3. **不用绝对阈值直接定级。** 不写 P0/P1/P2 这类等级——同一个 `BIAS=0` 在
   "全年有 1901 次强降水事件"和"全年零事件"下含义完全不同。
   结论要写成"事实 + 数值 + 条件化建议"。

---

## 1. 前置门槛（先过这一关，再谈技巧）

| 条件 | 判定 | 报告里应当怎么写 |
|---|---|---|
| `events = hits + misses = 0` | **不可评定** | "该量级观测事件合计为 0，属样本库的物理上限：技巧不可评定、不具备统计学意义，不是模型缺陷" |
| `0 < events < 50` | **仅参照** | "样本极少（N 次事件），方差大，仅供参考；补齐样本前不要据此调参" |
| `n_pairs = 0` | **无数据** | "无有效配对样本" |
| `TS = NaN` 但 `events > 0` | **无技巧** | "有事件但无命中，TS 不可定义（≠ 评分 0.000）" |

---

## 2. 技巧分级（TS）

| 标记 | 区间 | 含义 |
|---|---|---|
| 🟢 | TS ≥ 0.3 | 相对可用 |
| 🟡 | 0.2 ≤ TS < 0.3 | 勉强可用 |
| 🔴 | TS < 0.2 | 不可用于该量级 |

**注意**：这是用于快速沟通的**经验分级**，不是业务发布标准。业务可用性要**按量级分别确认**
（小雨的 0.3 与特大暴雨的 0.3 完全不是一回事）。

---

## 3. 偏差（BIAS，频率偏差）

`BIAS = (hits + false_alarms) / (hits + misses)`，理想值 1；**它不是平均误差**。

| 区间 | 含义 |
|---|---|
| 0.9 – 1.1 | 频率基本匹配 |
| 0.7 – 0.9 / 1.1 – 1.3 | 轻微偏少 / 偏多 |
| 0.5 – 0.7 / 1.3 – 2.0 | 明显偏少 / 偏多（需订正） |
| < 0.5 / > 2.0 | 严重偏少 / 偏多 |

**单独一个 BIAS 不能下结论**，必须与 FAR / 漏报率联合判读：

| | FAR 高 | FAR 低 |
|---|---|---|
| **BIAS 高** | 到处报（过度触发，空间平滑） | 报得少但报得准 |
| **BIAS 低** | 报得少也报不准 | 系统性漏报（阈值偏高/强度不足） |

---

## 4. 误差形态（FAR 与漏报率对比）

- `FAR > 漏报率` → 空报为主：抬高阈值、做频率匹配；
- `漏报率 > FAR` → 漏报为主：先保证不漏报（POD 优先），再压 FAR。

只在**同一等级**内比较这两个量；跨等级比较没有意义。

---

## 5. 时效衰减

同量级下比较首个与末尾时效的 TS：

- 绝对衰减：`TS(首) − TS(末)`；
- 相对衰减：绝对衰减 / `TS(首)`；
- 每天衰减：绝对衰减 / 时效跨度（天）。

经验判读：**相对衰减 > 50%** 或**每天衰减 > 0.01** 时，说明长时效已明显退化，
需要在报告里点名"长时效不可用"。

## 6. 概率评分（AROC / BSS）

> AROC / BS / BSS 由 `metrics/probabilistic.py` 计算，集合 TS 报告的概率节由
> `ts_report.analysis_probability` 渲染。本节只讲**判读**，定义见
> `evaluation-metrics.md` §2。

**先分清两个问题**：AROC 问"能不能把事件排出来"，BSS 问"概率数值准不准"。
两个都低是真没技巧；一高一低是常见组合，**不能互相顶替**。

| 指标 | 无技巧 | 有技巧 | 判读 |
|---|---|---|---|
| AROC | 0.5 | → 1 | ≥0.9 区分能力强；0.7–0.9 可用；<0.7 该量级基本分不开 |
| BSS | 0 | → 1 | >0.2 明显优于气候；0–0.2 略优于气候；≤0 不如直接报气候概率 |

**三条约束**：

1. **没有 `BS_ref` 就不要报 BSS。** 只有给了外部气候概率参考（`--ref`）的 6h 窗
   才有 `BS_ref`，其余窗口整列是 `—`。这种情况如实写"无气候基准，本次不给 BSS"，
   不要拿别的窗口的 BSS 顶上。
2. **高阈值档先看 `base_rate`，再看 BS。** ≥25mm 的 `base_rate` 常在 0.005 量级，
   一个永远报 0 的模型 BS 就已经很小——**BS 小不等于好**。这一档要看 BSS，
   并且先过第 1 节的样本量门槛（`n_points` 和事件数不是一回事）。
3. **AROC 与 TS 不能互相印证。** AROC 只看排序、对频率偏差不敏感，一个系统性
   高报的模型 AROC 可以很高而 TS 很低。两个都报时要写清各回答什么问题。

**不要做的事**：不要把 AROC/BSS 和 TS 画进同一张图（6h vs 24h 窗口、
阈值表不同、逐成员 vs 集合平均场口径不同）；不要用 `AVG` 档代替逐档结论
（它是**可算阈值的等权平均**，无事件的档被跳过了）。

## 7. 改进建议的触发条件

建议只在条件成立时出现（与报告的「改进建议」一节一致）：

| 触发条件 | 建议 |
|---|---|
| 小雨量级 `BIAS > 1.3` 且 `FAR > 0.45` | 模型倾向"到处报小雨"、空间过度平滑 → 焦点损失（Focal Loss）降低无雨背景权重 + 频率匹配订正 |
| 强降水（≥25 或 ≥50mm）`TS < 0.15` | 高频细节丢失 → 空间谱损失（Spectral Loss）+ 极端事件样本重加权 |
| 某量级 `events < 50` | 先延长评估期或扩大统计区域补齐样本，再评该量级技巧 |
| 普遍 `BIAS` 偏高或偏低 | 后处理分位数映射（QM）/ 频率匹配（FM）同时压缩偏差与空报 |

---

## 8. 不要做的事

1. 不要把 `NaN` 当 `0` 报告；
2. 不要在样本不足时写"技巧最差"；
3. 不要用同一套绝对阈值套所有量级；
4. 不要跨口径比较（不同时段、站点集、窗口长度、阈值表的数据不可直接横向比）；
5. 不要在没有依据时写"模型物理过程有问题"这类因果结论——报告只陈述可验证的统计事实，
   因果要留给建模团队结合个例分析；
6. 不要把 AROC/BSS 和 TS 混进同一张图或同一个结论——窗口、阈值表、样本口径都不同
   （见 §6）。
