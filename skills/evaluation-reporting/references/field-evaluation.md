# 连续场指标语义与判读（`weather_field_scores`）

本文件描述**确定性连续场检验结果怎么判读**。指标语义与判读规则与
`scripts/reporting/reports/field_report.py` 中的 `METRIC_SEMANTICS` /
`summarize()` / `diagnose()` **一一对应**，智能体写报告时以代码为准，
本文件用于解释口径和边界。改规则先改代码，再回来改这里。

覆盖流程：`weather_field_scores`。**能力身份认的是产物目录里 `manifest.json` 的
`resolved_config.pipeline`，不是目录名**（配置名与流程名本来就不绑定）。

> **现状：这一族的格式契约（`assets/templates/field_scores.md`）已删。**
> 能力本身、渲染器（`scripts/reporting/reports/field_report.py`）和本文件都还在，
> `render_report.py` 照跑不误；但报告"结构固定"这句话**没有真值来源了**——
> `tests/unit/visualization/test_field.py` 原先是对着那份骨架逐字比对的，
> 骨架一删，它再红也说不清是渲染器变了还是骨架没了。
> 本文件描述的口径与判读规则**不受影响**（它们对的是代码，不是骨架）。

---

## 0. 三条原则

1. **只用数据内证据。** 连续场指标没有公认的绝对合格线，所以本链路**不做分级**
   （不打 🔴🟡🟢，不写"ACC ≥ 0.6 算合格"）。只在数据内部比大小、看形态。
2. **比值类只看偏离 1 的幅度与方向**，`activity_bias` 除外（它是差值，理想值 0）。
3. **跨变量的原始值不可直接比大小**，因为单位随数据源走（见第 3 节）。

---

## 1. 长表里的 7 个 `metric`

| `metric` | 中文名 | 参考线 | 方向 | 是什么 |
|---|---|---|---|---|
| `rmse` | RMSE | 无 | 越小越好 | 均方根误差。**没有理想值**，所以不画参考线，只看它随时效涨多快 |
| `acc` | ACC（距平相关） | 1.0 | 越大越好 | 距平场的空间相关。本流程是 **uncentered** 口径（FDP / WeatherBench2），不是经典皮尔逊 |
| `activity_ratio` | 活跃度比（预报/实况） | 1.0 | 越接近 1 越好（**两侧都坏**） | 距平标准差之比。<1 偏平滑（能量不足）、>1 偏噪（能量过量） |
| `activity_bias` | 活跃度偏差（预报−实况） | 0.0 | 越接近 0 越好 | 与 `activity_ratio` 同号、信息重复，只进表格不进图 |
| `activity_forecast` | 预报活跃度 | 无 | — | 预报的距平标准差（原始量，不是技巧分） |
| `activity_observation` | 实况活跃度 | 无 | — | 实况的距平标准差（`activity_ratio` 的分母） |
| `spectrum_power_ratio` | 纬向谱功率比 | 1.0 | 越接近 1 越好 | **全波数求和后**预报总功率 / 实况总功率 |

> `activity_forecast` / `activity_observation` 是**原始量**，没有理想值，
> 也没有参考线；它们的作用是把 `activity_ratio` 拆开——比值 0.8 到底是
> 预报偏弱还是实况偏强，看这两个数才知道。

**变量与指标不是满交叉**：每个变量只算被逐变量路由到的指标
（`z500` 有 ACC，`q700`/`t850`/`msl` 没有；活跃度只有 `z500`/`u*`/`v*`/`ws850` 有）。
看到某变量"没有某个指标"，先查 `manifest.json` 的 `metric_options`
（每个指标带着自己的 `variables` 列表），再怀疑缺数据。

## 2. 判读规则（与 `diagnose()` 对齐）

报告执行摘要里的每一条**都必须带具体数值**，规则如下：

| # | 规则 | 报告里怎么写 |
|---|---|---|
| 1 | 覆盖与规模 | "共 N 行（`status=success` M 行），覆盖 X 个变量、Y 个指标，时效 a–b h 共 Z 个" |
| 2 | 非 success 行 | 有多少行、各是什么状态；这些行的 `value` 不可当结论 |
| 3 | 该算但没出数 | 列出缺席的「变量 × 指标」组合。**成因从结果反推不出来**，如实说"看评测日志" |
| 4 | RMSE 增长 | 按「末/首」倍数排序，点名最快与最慢的变量，给出首末值与倍数（倍数单位无关，可跨变量比） |
| 5 | RMSE 单调性 | 误差随时效累积**本该**单调上升；非单调的变量逐个点名，拐点值得回看原始场 |
| 6 | ACC 衰减 | 首末时效的绝对衰减与相对衰减（%），并说明是否单调。**不设合格线** |
| 7 | 活跃度比 | 按 `\|ratio − 1\|` 排序，点名偏离最大的几个 + 方向（<1 偏平滑 / >1 偏噪），给出 <1 与 >1 的变量个数 |
| 8 | 谱功率比 | 同 7，并**必须**加一句：这个比值是全波数求和后的，总量正常也可能掩盖分布失真，要定位波段得看谱曲线 |
| 9 | 时效覆盖不齐 | 某指标下变量之间的时效数不一致时点名；缺的时效在长表里**整行都没有**，不是 `value` 为空 |

## 3. 口径与坑

### 3.1 单位随数据源走，跨变量不可比

| 数据源布局 | z500 的 RMSE 单位 | 说明 |
|---|---|---|
| `*_phys`（fuxi_phys / era5_zarr 等） | `m^2/s^2` | **不除 g**。1 m²/s² ≈ 0.102 m |
| 老 layout（`fuxi` / `fengqing`） | `m` | 按 `1/g` 换算过 |

同一批结果里：`q` 是 `g/kg`、`t` 是 `K`、`msl` 是 `Pa`、`u/v/ws` 是 `m/s`、
无量纲的写 `1`。

> 复用 `fuxi_phys` 布局读 AIFS / FengQing 的目录式输出时，它们的 q 落盘是
> **kg/kg**（FuXi 是 g/kg），配置里必须写 `"scales": {"q700": 1000.0}`。
> 漏写时 q700 的 RMSE 会退化成实况场自身的量级（~4 g/kg），且 AIFS 与
> FengQing 会得到逐位相同的数值——看到这个指纹先查单位。

所以：

- **RMSE 折线图按单位分面**（一个单位一个子图），面与面之间不可直接比大小；
- **热力图填"相对首时效的倍数"**（除过首时效之后无量纲），行标签里同时写上
  首时效的绝对值，尺度不丢。

### 3.2 `n_valid` 的含义不统一

| 指标 | `n_valid` 是什么 | 典型值 |
|---|---|---|
| `rmse` / `acc` / `activity_*` | **格点数** | 全球 0.25° = 1038240 |
| `spectrum_power_ratio` | **参与平均的二维场个数** | 单起报单时效 = 1 |

谱行的 `n_valid = 1` 是结构性的，**不是"样本只有 1 个"**，不能用来判断结果可不可信。

### 3.3 其他

- **`value` 为空 ≠ 0**：为空说明这个组合没算出来，看同行 `status`。
- **`level` / `region` / `threshold` / `window_h` / `weights_id` 恒为空**：
  这是 `grid_valid_time` 协议 `defaults()` 的设计（默认口径只有
  `variable` / `sample_unit` / `unit`），不是缺数据。
- **`group` 列在 `scores.csv` 里**（2026-09 起随 `SCORE_COLUMNS` 落盘，此前被
  `reindex(columns=SCORE_COLUMNS)` 剥掉了）：球谐带行是带名（`1_4` / `5_20` …），
  其余指标为空。按 `(variable, metric, lead_h)` 透视球谐指标时**必须带上 `group`**，
  否则 5 个带会被平均成一个数。
- `diagnostics/scores_detail.csv` 里的 `group` 是另一套口径：逐波数谱用
  `k=<波数>`，总功率行用 `summary`。
- **首/末时效不是稳定的统计量**：起报数与时段决定曲线形态，
  "涨到几倍"只在当前这套输入下成立；跨批次比较要用同样的起报集合。
- **逐波数谱曲线在 `diagnostics/scores_detail.csv`**，`group=k=<波数>` 行里
  有 `wavenumber` / `power_forecast` / `power_observation` 三个字段，
  另有 `group=summary` 行给总功率。文件很大（实测 90 万行），**默认不读**。

---

## 4. 不要做的事

1. 不要给连续场指标编绝对合格线或分级（没有权威来源）；
2. 不要把 `spectrum_power_ratio` 的 `n_valid=1` 当样本量写进报告；
3. 不要把不同单位的 RMSE 画在同一根纵轴上比大小；
4. 不要把 `NaN` / 空 `value` 当 0 报告；
5. 不要拿 `spectrum_power_ratio` 断言"谱分布没问题"——它只是一个总量比值；
6. 不要用"结果里没有"反推"数据源里没有"（成因在评测日志里，报告只陈述缺席事实）；
7. 不要跨口径比较（不同时段、不同起报集合、不同 `max_wavenumber` 的结果不可直接横向比）。
