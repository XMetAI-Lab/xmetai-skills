# 确定性降水分类检验报告骨架（多模型对比）

覆盖**确定性**两条流程 `weather_ts_det` / `fdp_precip_ts`（TS / POD / FAR / 频率偏差），
渲染器是 `scripts/reporting/reports/ts_report.py`，输入是产物目录里的
`diagnostics/categorical_wide.csv`。**按能力家族分文件**，所以这两条流程共用这一份。

**只有一份骨架**：就是多模型对比这一份。主模型由 `--model`（或 manifest 的 `run_id`）
给出，对比模型由 `--compare 名字=CSV路径` 逐个追加（可重复），**全部列在同一张表里**。
只有一个模型时照样走这一份——那是 N=1 的退化形态（「最佳」列与模型列重复、
总体表只有一行），不是渲染错误，**不要另开一份单模型骨架**。

集合那条 `weather_ts_ens` **单独成篇**，见 [`weather_ts_ens.md`](./weather_ts_ens.md)：
章节骨架与本节逐字相同（TS 同样算在集合平均场上），但多一节 §4.7 概率评分（AROC / BSS），
**后面的图号整体后移两位**——§4.7 的 AROC / BSS 各占图 9、图 10，§5 的分时效点图在确定性报告里是图 9、在集合报告里是图 11。

**照这个填空就是最终报告。** `{…}` 是占位符，**其余每一个字逐字照抄，不许改**——
包括标点、加粗、`•` 项目符号、`>` 引用块、表头与分隔行、图注的位置。
`{…}` 里的字样只是填充说明，**不要原样抄进报告**；`{` 和 `}` 必须在同一行，占位符不要跨行写。

**章节组织**：`# 1.`…`# 6.` 六章 + 附录。每张表由它上方的**粗体小标题**引导（**表不编号**），
**图随分析节放在正文里、按出现顺序连续编号**（`图 N：`，图注在图下方）。这样做是因为报告里
有**条件章节**（附 L 分纬度带可能整块没有），表一旦参与全局编号，条件章节一消失后面全要重排。

**第 4 章的组织方式**：章首给总体排序与基准时效的分等级对照（热力图 + 分组柱）；
其后 **TS / POD / FAR / BIAS 各占一节**，每节固定按「引导句 → 表 → 图 → 判读 → 分析」排列；
最后是 4.5 跨时效稳定性、4.6 性能图（集合报告再加 4.7 概率评分）。
§5 把各等级等权平均压成「一条时效一个数」，回答「换一个时效，领先者会不会换人」。

**图号契约**（确定性）：`图 1`（§4 开头的总体指标热力图）、`图 2`（§4 开头的基准时效分组柱）、
`图 3`（§4.1 TS 随时效）、`图 4`（§4.2 POD 随时效）、`图 5`（§4.3 FAR 随时效）、
`图 6`（§4.4 BIAS 随时效）、`图 7`（§4.5 箱线图）、`图 8`（§4.6 性能图）、
`图 9`（§5 分时效点图）**全部必出**。附录独立命名空间 `图 L1`，
整块可缺——缺时写「本批未出」及原因，**不留空号、也不指不存在的文件**。

**条件块与缺数据形态**（骨架写的是有数据时的完整形态；缺数据时按下面的规则整段收口）：

- **附 L**：共同的 `region` 行不存在时，整块只保留标题与「**本块本批未出。** …」一句，
  后面的表、判读、图 L1 全部不出现；这一块也不进正文 `图 1..N` 的连续性检查。
- **强降水档**：全批没有 ≥25mm 的等级时，§4 总体表的列名退化为「强降水TS」（不带阈值），
  §4 总体判读里的强降水条也整条不出现——这是渲染器的收口方式，**不要自己补一个阈值**。

**口径约定**：

- `{强降水门槛}` 是全批 ≥25mm 的**最小一档**（`HEAVY_RAIN_THRESHOLD`），全批同一个门槛；
- `{基准时效}` 是 §4 开头分组柱与 §4.6 性能图用的那一个时效，默认取**首个时效**
  （`build_ts_report(lead_h=None)`），报告里一律写成 `{24}h` 这种形式；
- 「全时效平均」是**各时效等权平均**（不是按样本数加权）；逐等级的比率一律**先合计列联表
  再算比率**（`TS_sum` / `POD_sum` / `FAR_sum` / `BIAS_sum`），不是逐时效先算比率再平均；
- 宽表**没有起报日期列**，所以 §2 只说配对样本、不写日期跨度；各份来源的起报日数
  差异只能从配对样本的比值反推。

**判读句都由渲染器生成**（`_analysis_overview` / `_analysis_grades` / `_analysis_leads` /
`_analysis_metric` / `_analysis_far_bias` / `_analysis_stability` /
`_analysis_performance` / `_analysis_lead_rank`），
图注由 `_captions` 生成。骨架里标了 `{判读…}` 的地方**必须**有内容，条数随数据变
（单模型时只出一条、并列时写「并列领先」），缺了就是渲染器坏了。

**第 4 章每小节末尾的「分析」段由智能体补写**（渲染器不出这一段）：位置在该节
`•` 判读之后，一段话、不分点、3–6 句。固定写四件事——(1) 这个指标衡量什么、
怎么读（方向、与相邻指标的关系）；(2) 主要形态（随量级或时效怎么走，给首末值、
保留率、落差这类具体数）；(3) 模型差异（谁领先、领先多少、在哪些格上一致或翻转；单模型时改写为各量级、
各时效之间的差异）；
(4) 一句业务含义或口径提醒。数字只能取自本报告的表与图，或由这些数字直接算出的
差、比、百分数，**不得引入报告里没有的数**。骨架里标 `{分析…}` 的位置必须真有这一段。

**`{生成时间}` 是报告生成时刻**（`datetime.now()`，精确到分钟），**不是数据末日期**——
数据覆盖到哪一档，§2 的配对样本列已经交代了。代价是产物**不逐位可复现**：
同一天同一分钟跑两次一样，隔天跑就不同。

> **本骨架目前没有自动化测试守着**：本仓库 `tests/` 里没有 `test_ts_report.py`，
> 也没有逐字扫描模板的测试。改 `ts_report.py` 的渲染后，**必须拿真实产物重跑，
> 并按本文件的章节顺序逐节对**；图号只在渲染器里压（`_Numbering` 跟着实际出图现算）。
