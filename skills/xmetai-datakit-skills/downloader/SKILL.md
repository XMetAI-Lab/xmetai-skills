# XMetAI Datakit Downloader

把用户的数据需求变成**可核对的下载配置、计划和本地原始文件**。
本 skill 依赖 Datakit 仓库；自带配置模板和带来源的候选说明，
不携带另一份下载实现或权威变量注册表。

## 输入与输出

输入可以是自然语言需求，也可以是已有 Batch YAML。执行前必须明确：

- 数据源或数据集、变量及含义；
- 日期范围、区域、时次或统计方式；需要时明确气压层或深度；
- 本地输出目录（必须与用户确认；未指定时提议 `~/xmetai-downloads/<任务名>/`，
  不要默认写入 skill 仓库、`output/` 或源码目录），以及预览还是正式下载。

缺少决定数据含义的信息时，一次问一个问题。不默认全球、不替换变量、不扩大日期。
CDS 当前按整月请求；用户要求月内部分日期时，说明限制，不静默下载整月。

输出分两阶段：

| 阶段 | 产物 |
|---|---|
| 规划 | Profile / Batch YAML、实际任务计划、待确认的需求摘要 |
| 执行 | 原始数据文件、下载状态记录、下载报告（参数、实际路径、成功 / 失败 / 跳过及检查范围） |

下载完成不等于文件科学完整性验收通过，也不等于标准训练数据集已构建。

## 工作流

### 1. 定位仓库与数据源

入口位于 [scripts/run_download.py](./scripts/run_download.py)。
按入口实际位置的祖先目录寻找 Datakit；技能仓库与 Datakit 分开时，
必须传 `--repo-root /absolute/path/to/xmetai-datakit`。
找不到仓库或下载器就停下，不尝试替代实现。

- CDS：ERA5 / ERA5-Land，见 [CDS 说明](./references/cds.md)。
- Copernicus Marine：当前配置为 ORAS5，见 [Marine 说明](./references/marine.md)。
- 不支持的数据源或变量：明确指出缺口，不凭名称套用现有数据集。

### 2. 对齐变量约定

先查 [Profile 模板与候选值](./references/profile-templates.md)，再按
[变量约定与边界](./references/variables.md) 核对当前下载器、数据集定义和 schema，
确认外部变量名、层次与统计口径。Datakit 中的 Profile 是示例，不是默认任务或完整清单；
模板注释中的候选值也不是全部启用，以用户需求和任务 Batch 为准。
schema 中的标准产品单位不一定是下载原值单位，不能据此宣称已完成转换。

### 3. 准备配置

优先从 [Profile 模板](./references/profile-templates.md) 生成任务专用 Profile，
不要默认复制 Datakit examples 中的变量组合、区域、气压层或时次。
按需选择小时单层、小时气压层、小时陆面、对应日统计或 Marine ORAS5 模板。
模板注释包含字段说明及仓库候选值快照，不代表官方全集或任意组合均可用。
候选以外的变量先核对官方数据集和下载器规则；无需仅为新增变量而修改技能候选清单。
用户已提供 Profile 时先检查再使用，不强制重建；不覆盖共享配置或模板。
Batch 的相对 Profile 路径和存储根目录都以 **Batch 所在目录** 为基准。
生成 Batch 前必须与用户确认 `storage.root_path`：未指定时提议用户主目录下的
`~/xmetai-downloads/<任务名>/`（使用绝对路径），由用户确认后写入。不要默认使用
skill 仓库、`output/`、Datakit 源码目录或当前工作目录；配置、记录和下载文件
应与源码分开保存。

从 [CDS Batch 模板](./assets/templates/cds_batch.yaml) 或
[Marine Batch 模板](./assets/templates/marine_batch.yaml) 起步。
将 Profile 与 Batch 保存到任务目录，替换所有占位符；不明确的关键值先询问。
日期只放 Batch；日统计不混入小时 `time` 和格式字段，Marine 不混入 CDS 字段。
模板不是开箱即用任务，预览前检查 YAML 类型、残留占位符和实际路径。
保持低并发、有限重试；不要盲目继承示例中的高重试次数。

### 4. 离线预览并确认

以下命令中的 `<skill>` 是本成员目录，`<datakit>` 是 Datakit 仓库根，
`<batch>` 是实际配置文件：

```bash
python <skill>/scripts/run_download.py --repo-root <datakit> --source cds <batch>
python <skill>/scripts/run_download.py --repo-root <datakit> --source marine <batch> --plan-only
```

默认是 `--dry-run`，不连接远端，但底层下载器会写本地计划文件。
`--plan-only` 只生成目标清单。两者都不是认证或远端数据可用性检查。
预览仍需下载器的 YAML 依赖；缺依赖时按对应下载器 requirements 安装。

离线预览成功后，面向用户以 **“下载总览”** 为标题，不使用“预览通过”作为标题或
开场。总览用于执行前核对下载内容，不是内部检查结果通知，也不表示已通过认证、
确认远端数据可用或已提交下载请求。预览失败时先说明具体问题，不展示为配置就绪。

按“承接已确认需求 → 下载总览 → 当前状态 → 下一步选择”的顺序展示：

- 简短承接用户已选定的区域、时次与目录，不重新询问已确认的参数。
- 在聊天正文中用表格或简短分项列出数据源、变量及层次、区域、日期、时次或统计
  口径、时次数（可确定时）、任务数、文件组织和已确认的保存位置。
  参数以实际预览为准，不把请求数、文件数和时次数混为一谈。
  保存位置优先展示为可点击的目录链接；完整目标文件路径需要时单列，
  不让长路径打断说明或塞入选择框。
- 用一句话交代当前状态，例如“配置已准备就绪，尚未提交下载请求”。
  只有离线检查成功时才这样表述；不把本地检查说成远端验证。
- 文件体积未知时不编造估计，可自然表述为“文件大小以实际下载结果为准”，
  不堆叠“体积未知”“无法预计耗时”等短句。

首次正式下载须获得用户对具体计划（含输出根目录）的确认；配置改变后重新预览和确认。

#### CDS 排队提示与执行终端选择

正式提交 CDS 请求前，在下载总览后的正文中简短提示，例如：
“提交后可能需要等待 CDS 排队处理；文件大小以实际下载结果为准。”
不保证小区域、单变量、单层或少量时次能立即处理，也不承诺完成时间。
此时不提前解释 `accepted`，不将状态术语、Dashboard 链接和完整排队说明堆进确认问题。

总览与状态说明展示后，再单独询问如何执行。使用宿主的提问工具时，问题保持简短，
例如“接下来如何执行这份下载计划？”，不要在问题中重复整份总览、长路径或排队说明。
可提供以下选项，将本次具体计划的正式下载确认与终端选择合并：

- “开始下载，由 Agent 执行（推荐）”
- “给我命令，我在其他终端执行”
- “暂不下载，保留配置”

用户已明确选择执行终端时不重复询问终端；用户只要求“执行”且未指定终端时，采用
Agent 终端，但仍须完成具体计划确认。终端选择不代替认证和条款确认。

- **Agent 终端执行（默认）**：由 AI 在已确认的环境调用入口。等待期间只根据实际
  日志报告请求 ID、最后观测状态与已等待时长。实际收到 `accepted` 后再解释：
  “CDS 已接收请求，正在等待处理。”仅在已确认本地进程仍运行时补充
  “下载进程会继续等待，有状态变化时我会更新进度。”
  `accepted` 不表示已开始提取数据或传输；日志可能只在状态变化时更新，
  长时间没有新日志不等于进程卡死。
  无法取得排位、队列数量或预计时间时不编造；需要说明耗时时可写
  “CDS 暂未提供预计完成时间。”在等待阶段提供
  [CDS Live Dashboard](https://cds.climate.copernicus.eu/live) 供用户查看全站负载，
  不将全站排队量解释为本请求排位，也不保证换年份、月份或数据集更快。
  若引用统计，注明来源、更新时间和时区（未知则注明）。
  排队时可告知进程仍运行并结束当前回复，等待完成通知，不为保持回复而反复轮询。
  不因等待超过两分钟或全站拥堵而擅自停止、切换终端、重试或另行提交请求。
- **其他终端手动执行**：只提供基于本次已预览 Batch 的可复制正式命令，不由 AI
  同时启动下载。使用实际环境与绝对路径，对路径按目标 Shell 正确引用；命令包含
  `--repo-root`、`--source cds`、Batch 路径和 `--execute`，不含凭据或默认强制重下。
  若使用 conda，给出实际环境的激活命令或 `conda run --no-capture-output -n <环境>`
  前缀。提醒用户在同一下载机器和用户账号下运行，保留终端最终汇总和退出码。
  用户报告结束后再按第 6 步核对本地记录、文件并生成报告；未取得退出码则标为未知。

若请求已经在 Agent 终端执行，切换前先确认本地进程与服务端任务状态。停止本地
进程不保证取消 CDS 请求；当前下载器不能按未完成请求 ID 接管，直接重跑 Batch
可能重复提交。不要让用户在另一终端并行运行同一 Batch；先由用户在 CDS 任务页面
核对、取消旧请求，或获取已完成结果，再决定是否重新执行。仅有本地 started /
retrying 记录不代表服务端任务已取消。

此选择适用于已完成认证配置的 CDS 下载；密钥输入仍必须由用户在私有终端完成，
Marine 正式执行仍遵循下文的私有交互终端要求，不套用 Agent 终端默认值。

### 5. 认证与正式下载

认证由官方客户端使用，见对应参考文档。CDS 提供以下选项，先询问用户选择：

1. **本地交互向导**：让用户在实际下载机器、实际用户的私有终端运行
   `python <skill>/scripts/setup_cds.py`，选择 1，隐藏输入 token。
   同一个脚本自动识别系统，通过 `Path.home()` 定位官方客户端默认读取的用户级配置：
   Linux/macOS 为 `~/.cdsapirc`，Windows 为 `%USERPROFILE%\.cdsapirc`。
   POSIX 设置权限 0600；Windows 使用 PowerShell 设置并检查仅当前用户可访问的 ACL，
   在写入密钥前先保护空临时文件；权限设置失败就停止。已有普通文件须确认整文件替换，
   不跟随符号链接或 Windows reparse point。不具备隐藏输入条件时拒绝保存。
2. **手动配置指导**：使用 `python <skill>/scripts/setup_cds.py --manual`
   或交互菜单选 2，展示步骤，不读写凭据。
3. **全手动（零代码执行）**：AI 直接在对话中提供
   [全手动步骤](./references/cds.md#选项三全手动零代码执行)，不运行任何脚本、
   Shell 命令、依赖安装或认证探测，也不读写用户凭据文件或启动向导。
   若实际下载环境未知，仅询问 Windows 还是 Linux/macOS，以及是否为远程/WSL 环境。
   给出对应文件位置、配置格式、权限设置和条款说明，然后等待用户确认“已配置完成”；
   不要求用户发送文件内容、token、截图或配置输出作为证明。
   用户确认后从原任务断点继续，不强制运行向导或在线验证，不宣称认证已验证成功。
   此零执行限制适用于认证配置阶段；后续预览或下载仍按用户授权与计划确认规则执行。

AI 可以展示向导命令或手动指导，但**不得通过聊天工具、捕获输出的任务、管道或
自动输入工具代替用户运行密钥输入环节**。不向用户索要聊天中的 key，不读取或
展示已有凭据，不将真实密钥写入 Profile、Batch、源码、命令参数或日志。
本地向导可写官方用户级认证 YAML，这是唯一的凭据文件写入路径，不是任务 YAML。
存在 `CDSAPI_RC` / `CDSAPI_URL` / `CDSAPI_KEY` 覆盖时，向导仅提示变量名并停止；
请用户私下处理或选择手动路径，不读取或打印变量值。
配置保存不等于认证成功；向导不联网、不提交请求、不安装依赖。
数据集条款由用户本人接受；Marine 不套用 CDS 向导。
Marine 当前执行器在正式运行时调用 `copernicusmarine.login()`，允许用户在此时
自主输入用户名、密码或回应凭据覆盖确认，不要求必须事先单独登录。
因此正式 Marine 命令交由用户在实际下载环境的可交互私有终端运行；
AI 不在捕获输出的工具、管道或自动输入工具中接收或代填认证信息。
提前登录也不保证正式执行没有提示。用户输入期间不读取终端内容、不索要截图或密码。
用户报告结束后，核对本地计划、状态与文件；若无法取得本次退出码或汇总，
在报告中标为未知，不用历史记录推断本次执行成功。离线预览仍可由 AI 工具执行。

```bash
python <skill>/scripts/run_download.py --repo-root <datakit> --source cds <batch> --execute
python <skill>/scripts/run_download.py --repo-root <datakit> --source marine <batch> --execute
```

默认使用底层下载器的完成记录恢复。只有匹配的完成记录和目标文件同时存在才跳过。
这是任务级恢复，不保证文件字节级续传。
`--force-redownload` 只能与 `--execute` 一起使用；可能覆盖文件，必须单独确认。
修改区域、变量口径或网格时使用新输出目录，不覆盖另一批结果。

### 6. 核对与交付

检查进程退出码、最终汇总和实际状态记录。任务未结束不得报告完成；
非零退出或失败计数非零必须明确说明，保留失败记录并给出恢复命令。
正式执行结束后，无论成功、部分失败或已确认中断，按
[下载报告模板](./assets/templates/download_report.md) 核对并保存 Markdown 报告，
不能只在对话中说“下载完成”。优先运行
[scripts/render_download_report.py](./scripts/render_download_report.py)，从 Batch、
计划、状态记录、可选运行日志和文件属性生成初稿；它不联网、不读凭据、不验证文件
内容。AI 必须核对初稿、补充未自动检查项后定稿。入口脚本不会自动生成报告。

```bash
python <skill>/scripts/render_download_report.py <batch> \
  --plan <plan.txt> --status <status.jsonl> \
  --run-log <captured_output.log> --exit-code <code> \
  --request-id <id> --datakit-root <datakit> --source cds --strict
```

`--run-log` 为入口命令的捕获输出（含最终汇总）；未提供时报告会按状态记录推定。
退出码、汇总或状态记录缺失时不得用 0 或成功兜底；`--strict` 在证据异常时返回非零。

- 报告保存在该任务**实际计划文件所在的记录目录**，命名
  `download_report_<YYYYMMDDTHHMMSSffffffZ>.md`（UTC 时间），不覆盖历史报告。
  默认记录目录为 `storage.root_path/_records/<Batch文件名不含扩展名>/`；
  有自定义记录路径或命令覆盖时以实际运行路径为准。计划路径无法确定时先说明并确认
  报告保存位置；无法写入时明确报错，不宣称报告已生成。
- 对每个 Profile 分别列数据源、数据集、变量、日期、区域、气压层/深度、时次或统计
  方式、格式、版本选择和执行参数；明确配置/请求值与实际文件检查值的区别。
  数据集固有时间分辨率须有已核对依据，不从文件数量推断，不编造版本、单位或分辨率。
- 列出 Batch、Profile、数据目录、实际计划和状态记录的绝对路径。
  按本次计划目标核对文件存在性与实际大小，列出本次完成、历史完成并跳过、失败和未知
  状态的证据；不把整个数据目录的文件数当作本次下载数，不重复累加重试记录。
  追加式状态日志可能包含历史任务；须匹配本次请求/目标及执行时间范围，
  无法区分本次完成与历史完成时就标明未知，不能仅按路径认定匹配完成。
- 文件较多时可另存同目录完整文件清单，在报告中给出链接、数量和目录结构。
  退出码、汇总或状态记录缺失、损坏、互相矛盾时明确列出，不以零或成功兜底；
  文件缺失、零字节或残留 `.part.nc` 作为异常，不能直接宣称全部完成。
- 不读取凭据文件，不将原始终端转录或未经脱敏的错误整段复制进报告。
  未实际打开数据文件检查时，明确标注“未执行文件内容/科学完整性验收”。
  离线预览若需报告须标“仅预览”，不得列为已下载。

最后在对话中给出报告链接、下载内容摘要、数据位置及异常；任务进程仍运行时仅给进度，
不生成最终完成报告。报告不自动授权重试、强制覆盖或额外在线请求。
后续解压、转换、单位处理、标准数据集构建与校验属于其他流程，不自动启动。

## 硬性边界

- 不移动或复制已有下载器实现；执行逻辑和依赖仍在 Datakit 仓库。
- 不把候选快照当作权威变量表；字段规则以当前下载器为准，变量可用性以数据集为准。
  下载器不支持的数据源或请求结构须先扩展并验证仓库能力。
- 不绕过账户权限、服务限额或数据条款。
- 不默认把下载写入 skill 仓库、`output/` 或 Datakit 源码目录；
  `storage.root_path` 必须经用户确认。
- 不把预览、计划生成、文件存在当成正式下载成功。

## 验证

测试保存在 xmetai-skills 仓库根目录的
[tests/test_downloader_skill.py](../../../tests/test_downloader_skill.py) 和
[tests/test_downloader_report.py](../../../tests/test_downloader_report.py)。
在 xmetai-skills 仓库根目录运行：

```bash
python -m pytest -q tests/test_downloader_skill.py tests/test_downloader_report.py
```

前者只测试 `scripts/run_download.py`：用临时桩程序验证参数门控、路径定位、
命令转发和退出码传递，不测试文档、模板或真实下载器，不连接远端。
后者使用临时 Batch、计划、状态和文件证据测试报告渲染器，不联网、不读取凭据。
报告渲染器测试需要 PyYAML；两者都不需要配置真实 Datakit 仓库路径。

模板检查及可选的真实 Datakit 离线兼容性测试见
[README 测试说明](./README.md#测试)。离线通过不证明远端支持所选变量组合。
